# 복지기금 운영 효율화 프로그램

매월 작성하는 **금전출납부** 하나만 입력하면, 사내근로복지기금 **결산자료 전체**와
고용노동청 제출용 **운영상황 보고서**(근로복지기본법 시행규칙 별지 제15호서식)가
자동으로 작성됩니다.

브라우저에서 `index.html`을 열면 바로 실행됩니다. 설치·빌드·서버가 필요 없습니다.

---

## 1. 무엇을 자동화했는가

기존 작업은 금전출납부를 쓴 뒤, 같은 거래를 원장 4곳에 다시 옮겨 적고, 시산표를 맞추고,
보고서 항목을 손으로 계산해 채우는 구조였습니다. 이 프로그램은 **최초 입력 이후의 모든 단계**를
없앱니다.

```
                    ┌─────────────────────────────────────────────┐
   금전출납부  ───▶  │  분류 엔진 (rules.js)  →  계산 엔진 (engine.js) │
   (유일한 입력)      └─────────────────────────────────────────────┘
                                        │
        ┌───────────────┬───────────────┼───────────────┬────────────────┐
        ▼               ▼               ▼               ▼                ▼
     보통예금         대출금         지급준비금        사업수익      대출 내역서
      원장            원장            원장             원장         (사업장별)
        └───────────────┴───────┬───────┴───────────────┘
                                ▼
                      합계잔액시산표 → 재무상태표 · 손익계산서
                                ▼
                  운영상황 보고서 ①~(62)  +  전 구간 자동 검증
```

| 산출물 | 내용 |
|---|---|
| 원장 4종 | 보통예금 · 대출금 · 지급준비금 · 사업수익 (월계 · 누계 포함) |
| 결산서 3종 | 합계잔액시산표 · 재무상태표 · 손익계산서 |
| 보고서 | 별지 제15호서식 ①~(62) 전 항목 (천원 단위 자동 환산) |
| 대출 내역서 | 사업장별 차주 명세 및 소계 |
| 검증 | 월별 수입=지출, 시산표 대차, 자산=부채+자본, 지급준비금 검산, 대출 내역 대사, 미분류·수혜자수 누락 탐지 |

## 2. 도출한 회계 구조

2025년도 실제 장부(금전출납부 182행, 원장 4종, 결산서 3종)와 제출된 운영상황 보고서를
역산해 다음 규칙을 확정했습니다.

**현금은 잔액이 항상 0입니다.** 수입은 즉시 보통예금에 예입하고, 지출은 즉시 인출합니다.
그래서 금전출납부의 월 수입 합계와 월 지출 합계는 언제나 같습니다.

**이자 수익은 곧바로 지급준비금이 됩니다.** 대출이자·예금이자는 사업수익 대변에 계상되는 동시에
전액 지급준비금으로 전입됩니다. 사업수익 = 사업비용이므로 **당기순이익은 구조적으로 항상 0**입니다.

**전입 시점이 항목마다 다릅니다.**

| 항목 | 지급준비금 전입일 |
|---|---|
| 정기 그룹이자 (`○○○ 외 대출이자 상환`) | 그 달의 **말일**에 소속별로 합산 |
| 결산이자 | **발생일** (3·6·9·12월) |
| 개별 전액상환 이자 | **발생일** |

**목적사업비와 운영비는 지급준비금 차변(사용)입니다.** 따라서

```
기말 지급준비금 = 전기이월 + 당기 수익 총액 − (목적사업비 + 기금운영비)
```

**미상환액 반환은 총액/순액이 갈립니다.** 금전출납부와 보통예금에는 실제로 오간 **총액**이,
대출금·사업수익·지급준비금 원장에는 같은 달 같은 소속의 상환액에서 차감한 **순액**이 기록됩니다.
엔진은 두 금액(`eff` / `net`)을 분리해 원본 장부의 처리 방식을 그대로 재현합니다.

### 보고서 산출식

| 항목 | 산출식 |
|---|---|
| ㉑ 금융회사 예입·예탁 | ⑳ − ㉗ |
| ㉗ 근로자 대부 | 기말 대출금 잔액 |
| ㉙ 기금운용 수익금 | 당기 사업수익 총액 |
| ㉞ 이월금 등 | 전기이월 보통예금 |
| ㉟ · (62) 합계 | ㉗ + ㉙ + ㉞ |
| (56)(57)(58) | 거래유형별 목적사업비 합계 |
| (59) 소계 | ㊾ + (51)~(58) |
| (60) 기금 운영비 | 사무보조비·수수료·세금 등 합계 |
| (61) 잔액 | (62) − (59) − (60) |

금액은 원 단위를 **천원으로 절사**합니다(실제 제출본과 동일).

## 3. 사용 순서

1. **기금 정보 · 이월** — 법인 정보와 전기이월 잔액을 입력합니다 (연 1회).
   전기이월 잔액은 전년도 결산서의 기말잔액을 그대로 옮겨 적습니다.
2. **금전출납부** — 매월 거래를 입력합니다. 적요를 쓰면 거래유형·소속·관련자가 자동 분류됩니다.
   노란 배경은 자동 분류에 실패한 행이니 유형을 직접 지정하세요.
   기존 엑셀이 있다면 상단 **엑셀 가져오기**로 금전출납부 시트를 통째로 불러올 수 있습니다.
3. **수혜자수** — 목적사업비 행에는 수혜자수를 반드시 입력합니다. 보고서 인원란의 유일한 근거입니다.
4. **대출 내역서** — 연말 기준 차주별 잔액을 정리합니다. 합계가 대출금 원장 잔액과 자동 대조됩니다.
5. **검증 결과** — 전 항목이 통과(초록)인지 확인합니다.
6. **엑셀 내보내기** 또는 **인쇄 / PDF 저장**으로 제출본을 만듭니다.

입력을 줄이는 보조 기능으로 **여러 줄 붙여넣기**(엑셀에서 일·적요·금액 열을 복사)와
**전월 정기항목 복사**(매월 반복되는 상환·사무보조비 행 복제)를 제공합니다.

## 4. 파일 구성

| 파일 | 역할 |
|---|---|
| `index.html` | 화면 구조 |
| `style.css` | 스타일 |
| `rules.js` | 적요 자동 분류 규칙 (거래유형 14종) |
| `engine.js` | 계산 엔진 — 원장·결산서·보고서·검증 (순수 함수, DOM 비의존) |
| `app.js` | UI 및 파일 입출력 |
| `demo.js` | 예시 데이터 (금액·거래구조는 실제 사례, 법인정보·인명은 전부 가명) |
| `test/verify.js` | 회귀 검증 |
| `test/fixture-2025.json` | 검증용 금전출납부 106건 (인명 가명 처리) |

데이터는 브라우저 `localStorage`에 **연도별로** 저장됩니다.
다른 PC로 옮기거나 백업할 때는 **기금 정보 · 이월 → 백업 파일 저장(JSON)**을 사용하세요.

## 5. 검증

2025년도 실제 금전출납부 106건을 엔진에 투입해, 원본 결산자료 및 제출된 보고서와
**58개 항목이 원 단위까지 일치**함을 확인했습니다.

```bash
node test/verify.js
```

검증 대상에는 원장 4종의 기말잔액, 시산표 차·대변 합계와 잔액,
재무상태표·손익계산서 전 항목, 보고서 ⑳~(62), 월별 금전출납부 12개월 월계가 포함됩니다.

## 6. 알아둘 점

- **엑셀 가져오기/내보내기**는 SheetJS(CDN)를 사용합니다. 인터넷이 차단된 환경에서는
  내보내기가 자동으로 **CSV**로 대체되고, 가져오기 대신 **여러 줄 붙여넣기**를 쓰면 됩니다.
  나머지 기능은 모두 오프라인에서 동작합니다.
- 자동 분류는 규칙 기반입니다. 새로운 형태의 적요는 분류되지 않을 수 있으며,
  이 경우 화면에서 직접 유형을 지정하거나 `rules.js`의 `RULES` 배열에 패턴을 추가하세요.
- 저장소에 포함된 예시·검증 데이터는 **인명과 법인 식별정보를 모두 가명 처리**했습니다.
  금액과 거래 구조만 실제 사례를 따르므로 검증 결과는 그대로 유효합니다.
  실제 업무에는 **엑셀 가져오기**로 원본 파일을 직접 불러와 쓰세요. 불러온 데이터는
  브라우저 안에만 저장되며 외부로 전송되지 않습니다.
- 사업장 목록(`우성`, `본사`, `논산1본부` 등)은 `rules.js`의 `ORGS` 배열에 있습니다.
  다른 사업장을 쓴다면 이 배열만 고치면 됩니다.
- 대출 내역서의 차주별 잔액은 자동 계산되지 않습니다. 정기 상환이 `○○○ 외` 형태로
  묶여 기록되어 개인별 배분이 불가능하기 때문입니다. 연말에 한 번 정리하고,
  합계가 원장과 맞는지 검증 화면에서 확인하는 방식입니다.
